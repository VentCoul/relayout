# Relayout: інструкція користувача

Relayout виправляє текст, набраний не в тій розкладці або з увімкненим Caps Lock. Він живе в треї (Windows, Linux) або в рядку меню (macOS) з іконкою «Aя» і спрацьовує тільки на гарячу клавішу.

| Система | Стан |
| :---- | :---- |
| macOS | Працює |
| Windows 10 / 11 | Працює; виправлення Caps Lock ще не перевірене на реальній машині |
| Linux, X11 | Працює; перевірено у віртуальному X11-сеансі (Ubuntu 24.04), на справжньому робочому столі ще ні |
| Linux, Wayland | Частково, див. [Linux і Wayland](#linux-і-wayland) |

## Встановлення

### macOS

1. Перетягніть `Relayout.app` у теку «Програми» і відкрийте його.
2. Програма не підписана, тому під час першого запуску macOS може її заблокувати. Тоді відкрийте Системні параметри → Приватність і безпека й натисніть «Усе одно відкрити».
3. Після першого натискання гарячої клавіші macOS попросить дозвіл: натисніть «Відкрити Системні параметри» і ввімкніть Relayout у розділі «Універсальний доступ». Він потрібен, щоб програма могла надіслати `⌘C` і `⌘V`.

### Windows

1. Запустіть `Relayout_<версія>_x64-setup.exe`.
2. Програма не підписана, тому Windows може показати попередження SmartScreen: «Докладніше» → «Виконати в будь-якому разі».
3. Після встановлення Relayout зʼявиться в треї (можливо, під стрілкою `^`). Дозволів не потрібно.

### Linux

Встановіть пакет для свого дистрибутива (`.deb` для Debian / Ubuntu, `.rpm` для Fedora) або запустіть AppImage. Дозволів на X11 не потрібно. Про Wayland див. [окремий розділ](#linux-і-wayland).

## Як користуватися

Типова гаряча клавіша — `Ctrl+Shift+Space` (на всіх системах).

### Виправити розкладку

- **Останнє слово:** нічого не виділяйте, просто натисніть гарячу клавішу одразу після слова. `ghbdsn` → `привіт`.
- **Кілька слів або речення:** виділіть текст і натисніть гарячу клавішу. `Ghbdsn? zr cghfdb&` → `Привіт, як справи?`.

Напрямок (англійська → українська чи навпаки) визначається автоматично. Правильно набрані слова у виділенні не змінюються: `Привіт, zr cghfdb&` → `Привіт, як справи?`.

Після виправлення система сама перемикається на правильну розкладку, тож можна одразу друкувати далі.

Якщо текст виправлено помилково, натисніть гарячу клавішу ще раз: текст повернеться назад.

### Виправити Caps Lock

Текст, набраний з увімкненим Caps Lock, виправляється тією самою гарячою клавішею: `пРИВІТ, ЯК СПРАВИ` → `Привіт, як справи`. Після цього Caps Lock вимикається.

Якщо текст ще й набрано не в тій розкладці (`gHBDSN`), обидві помилки виправляються одним натисканням: `Привіт`. Чи треба міняти розкладку, програма вирішує сама. У сумнівних випадках (переважно дуже короткі слова) вона виправляє лише регістр, тоді для розкладки натисніть гарячу клавішу ще раз.

Не вважаються помилкою Caps Lock:

- текст повністю великими літерами (`NASA`, `ОК`), бо його могли написати так навмисно;
- з тієї ж причини слово, набране з Caps Lock в англійській розкладці, яке починається з `ю`, `б`, `ж`, `є`, `х`, `ї` чи `ґ`: `>HBCN` не відрізнити від навмисного `ЮРИСТ`. Виділіть його й натисніть гарячу клавішу: розкладку буде виправлено, а регістр доведеться виправити вручну.

## Налаштування

Іконка «Aя» → «Налаштування…»:

- **Гаряча клавіша.** Клацніть у полі й натисніть нову комбінацію. Вона має містити `Ctrl`, `Alt`, `Shift` або `⌘` / `Win`, або бути функціональною клавішею (`F1`–`F12`). Якщо комбінацію зайняла інша програма, зʼявиться повідомлення, а попередня лишиться.
- **Запускати разом із системою.**

Гаряча клавіша зберігається у файлі `settings.json`:

| Система | Шлях |
| :---- | :---- |
| macOS | `~/Library/Application Support/dev.relayout.desktop/settings.json` |
| Windows | `%APPDATA%\dev.relayout.desktop\settings.json` |
| Linux | `~/.config/dev.relayout.desktop/settings.json` |

Інших даних програма не зберігає.

## Як рідше помилятися з розкладкою

Багато помилок трапляється, коли переходиш між програмами, де пишеш різними мовами. Обидві системи вміють запамʼятовувати розкладку для кожної програми окремо, але за замовчуванням це вимкнено:

- **macOS:** Системні параметри → Клавіатура → Джерела введення → «Автоматично перемикатися на джерело введення документа».
- **Windows:** Параметри → Час і мова → Введення → Додаткові параметри клавіатури → «Дозволити використовувати інший метод введення для кожного вікна програми».

## Linux і Wayland

На X11 усе працює так само, як на інших системах. Підтримуються перші дві розкладки зі списку (наприклад, `us,ua`), будь-який варіант української.

Wayland навмисно не дозволяє програмам слухати глобальні гарячі клавіші й надсилати натискання в чужі вікна. Тому під Wayland:

- Гарячу клавішу треба призначити в налаштуваннях системи на команду `relayout --convert` (GNOME: Параметри → Клавіатура → Власні комбінації; KDE: Параметри системи → Комбінації клавіш). Relayout при цьому має бути запущений.
- Виправлення спрацює лише у програмах, що працюють через XWayland (часто це Electron-програми). У «рідних» Wayland-програмах — ні.

Під GNOME перемикання розкладки після виправлення може не спрацювати навіть на X11, бо GNOME керує розкладками сам. Це не перевірено.

## Обмеження

- Підтримуються англійська та українська мови.
- У полях паролів не працює: система не дає їх копіювати.
- На Windows не працює у вікнах, запущених від імені адміністратора.
- На Windows і Linux виправлення починається, коли відпущено всі клавіші гарячої комбінації.
- Редактори коду (наприклад, VS Code), які за `Ctrl+C` без виділення копіюють увесь рядок, у режимі «без виділення» отримають виправленим увесь рядок. У них виділяйте текст явно.
- Якщо в буфері обміну перед виправленням були файли (а не текст чи зображення), вони не відновляться.

## Приватність

- Програма не стежить за клавіатурою: вона дізнається лише про натискання гарячої клавіші.
- Програма нічого не надсилає в мережу і не має автооновлень.
- Текст ніде не зберігається і не записується в логи. Він існує в памʼяті лише під час одного виправлення.
- Виправлений текст позначається для менеджерів буфера обміну як прихований, тож не потрапляє в історію буфера (`Win+V` тощо). Попередній вміст буфера повертається одразу після вставки.

## Типові проблеми

| Проблема | Що робити |
| :---- | :---- |
| **macOS: гаряча клавіша нічого не робить** | Перевірте, що Relayout увімкнено в Системні параметри → Приватність і безпека → Універсальний доступ. |
| **macOS: після оновлення програма знову просить дозвіл, хоча перемикач увімкнено** | Нова збірка не підписана, тож macOS вважає її іншою програмою. Закрийте Relayout, виділіть його в списку «Універсальний доступ», натисніть **−**, знову відкрийте Relayout і дайте дозвіл. |
| **«Комбінація зайнята іншою програмою»** | Оберіть іншу гарячу клавішу в налаштуваннях. |
| **Слово виправилось, але розкладка не перемкнулась** | Трапляється в окремих програмах і під GNOME. Перемкніть розкладку вручну. |
| **Замість `є` лишився апостроф** | Виправлено у версії з підтримкою типографських лапок. Оновіть програму. |
| **Текст повністю великими літерами не виправляється з Caps Lock** | Так задумано: див. [Виправити Caps Lock](#виправити-caps-lock). |
| **Linux: гаряча клавіша не працює** | Найімовірніше, у вас Wayland: див. [Linux і Wayland](#linux-і-wayland). |
| **Windows: не працює в одній конкретній програмі** | Перевірте, чи вона не запущена від імені адміністратора. |
